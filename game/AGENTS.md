# game/AGENTS.md - Godot 4.7.2 Project & GDScript Rules

These rules apply to all files inside `game/` (`res://`), including scenes, scripts, autoloads, resources, export presets, and automated tests for the **Sudoku** project.

---

## 1. File Encoding & Resource Integrity

- **UTF-8 Without BOM Only:** Godot's parser rejects `.tscn`, `.tres`, `.gd`, and `.cfg` files containing a UTF-8 Byte Order Mark (BOM) or UTF-16 encoding. Always create and edit files inside `game/` using the agent's native `write_file` and `edit_file` tools, never via PowerShell stream redirection (`>`).
- **Blank Line in `.tres` Resources:** When generating or editing `.tres` resource files manually, always preserve a blank line between the `[gd_resource ...]` / `[ext_resource ...]` headers and the `[resource]` block.
- **Commit `.uid` Files:** Stage and commit any `.uid` files generated by Godot alongside new or moved `.gd` scripts, scenes, and resources.
- **Export Filters for Non-Resource Files:** Godot's `export_filter="all_resources"` skips plain data files (`.txt`, `.json`, `.csv`, `.ttf`) unless matched in `include_filter`. Ensure `*.ttf, *.txt, *.json` is listed in `include_filter` for both the `Android` and `Web` presets in [`game/export_presets.cfg`](export_presets.cfg).

---

## 2. GDScript Coding Standards

1. **Strict Static Typing:**
   - Every variable, constant, function parameter, and return type must have an explicit type annotation (`var current_row: int = 0`, `func evaluate_cell(row: int, col: int) -> bool:`).
   - Avoid untyped `:=` inference when the right-hand side returns `Variant` (such as `get_node()`, `Dictionary.get()`, or `JSON.parse_string()`). Explicitly annotate the variable type and cast with `as`:
     ```gdscript
     var title_label: Label = get_node_or_null("Header/Title") as Label
     ```
2. **Naming Conventions:**
   - **Classes (`class_name`) & Scene Nodes:** `PascalCase` (e.g., `SudokuBoard`, `CellUI`, `GameplayScreen`)
   - **Functions, Variables & Signals:** `snake_case` (e.g., `selected_cell`, `_on_number_pressed()`, `game_won`)
   - **Constants & Enum Values:** `UPPER_SNAKE_CASE` (e.g., `GRID_SIZE = 9`, `COLOR_BG_DEFAULT`)
3. **Logging:**
   - Do not leave raw `print()` calls in gameplay, UI, or domain scripts.
   - Use `print_debug(...)` for diagnostic traces, `push_warning(...)` for recoverable anomalies, and `push_error(...)` for broken invariants.
4. **Documentation:**
   - Include a top-level `##` doc comment on every autoload and domain script describing its responsibility.

## 3. UI Layout, Styling & Cross-Platform Guardrails

- **1930s Monochrome Aesthetic:**
   - All custom containers, cards, and dialogue panels in `.tscn` scenes must bind to `res://resources/theme_1930s.tres` or define explicit `StyleBoxFlat` borders (2px white borders, 8px rounded corners, `#121212` backgrounds, and content margins).
   - Dynamic styling based on game state (e.g., highlighting selected rows/cols/boxes, error red highlights, or completed number dims) should use runtime GDScript theme overrides (such as `add_theme_color_override` or `add_theme_stylebox_override`).
- **Web/HTML5 Font Fallbacks:**
   - Browser WASM exports have no access to host OS system fonts. Never assign a bare `SystemFont` as the default font or theme font.
   - UI themes and controls must use `res://resources/theme_1930s.tres` with `res://assets/fonts/NotoSansSymbols-Regular.ttf` and `res://assets/fonts/DejaVuSans.ttf` attached to the `fallbacks` array of its `FontVariation`.
   - Whenever adding Unicode symbols or icons (`☰`, `✕`, `▸`, `▾`, `★`, `↺`, `↻`, `⌫`, `▶`, `→`) to UI controls, add a unit test asserting `font.has_char(ord(ch))` against the active theme font.
- **Responsive Portrait Layout & Safe Areas:**
   - The base logical viewport is `720x1280` portrait (`canvas_items` stretch mode, `expand` aspect).
   - Full-screen UI screens must account for mobile notches and system bars via `DisplayServer.get_display_safe_area()` during `_ready()` and `NOTIFICATION_RESIZED`.
   - When using `GridContainer` (such as the 9x9 board or 1-9 numpad), remember that Godot natively collapses invisible children (`visible = false`). To keep grid slots fixed, keep nodes visible and clear text (`text = ""`) or set `modulate.a = 0.0`.
- **Post-Game State Management:**
   - When clearing game state after a win or reset, always call `SaveManager.clear_active_game()` rather than a bare `SaveManager.clear_save()`. This ensures in-memory states (current difficulty, puzzle string, timer) are cleared so focus-loss events do not re-save a completed game.

## 4. Automated Unit Testing (`game/tests/`)

- **Test Suite Location & Naming:** Place unit test scripts in `game/tests/test_<feature>.gd`. Every script must extend `TestBase` (`res://tests/test_base.gd`) and define `func test_<case>() -> void:` methods.
- **Lifecycle Hooks:** Override `before_each() -> void` and `after_each() -> void` on `TestBase` subclasses for per-test state setup and cleanup, or `cleanup() -> void` for suite-level teardown.
- **Available Assertions in `TestBase`:**
  - `assert_true(condition, message)` / `assert_false(condition, message)`
  - `assert_eq(actual, expected, message)` / `assert_ne(actual, expected, message)`
  - `assert_gt(actual, expected, message)` / `assert_gte(actual, expected, message)`
  - `assert_lt(actual, expected, message)` / `assert_lte(actual, expected, message)`
  - `assert_approx(actual, expected, tolerance, message)`
  - `assert_null(val, message)` / `assert_not_null(val, message)`
  - `assert_contains(haystack, needle, message)`
  - `assert_file_exists(path, message)`
- **Headless Test Runner Caveats:**
  - `test_runner.gd` extends `SceneTree` directly and runs during `_init()`. Global autoload singletons defined in `project.godot` are not registered as global identifiers during headless runner execution. Avoid hardcoding global singleton identifiers directly inside core logic classes or autoloads; look up peer singletons dynamically via `/root/SingletonName` or `Engine.get_main_loop().root.get_node_or_null("SingletonName")`.
  - When instantiating `Node` or `Control` subclasses in tests, add them to `test_root_window.add_child(node)` if `_ready()` or theme propagation is required, and always destroy them immediately using `node.free()` (never `queue_free()`, which leaks objects on headless exit).
  - Lambda closures in GDScript capture primitive types (`int`, `bool`, `float`, `String`) by value. To count signal emissions inside a test lambda, mutate an `Array` wrapper (e.g., `var count: Array[int] = [0]`).
  - Guard `DisplayServer` window/screen state assertions with `if DisplayServer.get_name() != "headless":`.
